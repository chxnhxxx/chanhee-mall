# 실행·구조 안내 (비개발자용)

이 문서는 **내 컴퓨터에서 쇼핑몰을 켜고 끄는 법**, 자주 쓰는 명령어의 뜻, 그리고 **어떤 폴더에 무엇이 있는지**를 설명합니다.

- 모르는 말이 나오면 [용어 사전](GLOSSARY.md)을 보세요.
- 외부 서비스 가입은 필요 없습니다. 키가 하나도 없어도 "데모 모드"로 전부 동작합니다.
- 이 PC 기준으로 적었습니다: Windows 11, 프로젝트 폴더 `~\OneDrive\Desktop\claude\chanhee-mall`
  - `~` 는 **내 사용자 폴더**(`C:\Users\내 이름`)를 줄여 쓴 표시입니다. PowerShell 에 `~` 를 그대로 쳐도 알아듣습니다.

---

## 한눈에 보기: 쇼핑몰 켜는 3단계

1. 터미널(PowerShell)을 연다
2. 프로젝트 폴더로 이동한다: `cd ~\OneDrive\Desktop\claude\chanhee-mall`
3. `pnpm dev` 를 입력하고, `Ready` 가 보이면 브라우저에서 http://localhost:3000 을 연다

처음 한 번만, 3단계 전에 `pnpm install` 을 실행합니다. 아래에서 하나씩 자세히 설명합니다.

---

## 1. 터미널 여는 법

터미널은 **글자로 컴퓨터에 지시하는 창**입니다. 다음 중 편한 방법 하나를 쓰세요.

- **Windows 시작 메뉴:** 시작 버튼 → `PowerShell` 입력 → "Windows PowerShell" 클릭
- **폴더에서 바로 열기 (추천):** 파일 탐색기로 `chanhee-mall` 폴더를 연 뒤, 빈 곳에서 **마우스 오른쪽 클릭 → "터미널에서 열기"**. 이렇게 열면 2단계(폴더 이동)를 건너뛸 수 있습니다
- **VS Code:** 프로젝트 폴더를 연 상태에서 메뉴 "터미널 → 새 터미널" (단축키 ``Ctrl+` ``)

열리면 이런 줄이 보입니다. 이 줄을 "프롬프트"라고 하고, `>` 앞이 **지금 있는 폴더**입니다.

```
PS C:\Users\(내 이름)>
```

**명령어 입력 요령**

- 이 문서의 회색 상자 안 글자를 복사해서 터미널에 붙여 넣고 **Enter** 를 누르면 됩니다.
- 터미널에서 붙여 넣기는 **마우스 오른쪽 클릭**이 가장 확실합니다. (Ctrl+V 도 대부분 됩니다)
- 터미널에서 **Ctrl+C 는 "복사"가 아니라 "지금 하는 일 멈춤"**입니다.

## 2. 프로젝트 폴더로 이동하기

명령어는 **지금 있는 폴더를 기준으로** 동작합니다. 그래서 먼저 쇼핑몰 폴더로 들어가야 합니다.

```powershell
cd ~\OneDrive\Desktop\claude\chanhee-mall
```

- **뜻:** `cd` = change directory, "이 폴더로 들어가"
- **정상:** 프롬프트가 `PS ~\OneDrive\Desktop\claude\chanhee-mall>` 로 바뀝니다
- **자주 나는 오류:** `경로를 찾을 수 없습니다` → 폴더 이름에 오타가 있거나, 폴더가 옮겨졌습니다. 파일 탐색기에서 폴더를 열고 주소창을 클릭하면 정확한 경로가 나오니 그걸 복사해 쓰세요

## 3. 처음 한 번: 부품 설치 (`pnpm install`)

```powershell
pnpm install
```

- **뜻:** 쇼핑몰이 쓰는 **부품(남이 만든 코드 묶음) 수백 개를 인터넷에서 내려받아** `node_modules` 폴더에 넣습니다. 레고 설명서(`package.json`)를 보고 필요한 블록을 사 오는 것과 비슷합니다.
- **언제:** 처음 한 번. 그리고 제가 "부품을 추가했다/버전을 올렸다"고 말씀드린 뒤에 한 번 더.
- **걸리는 시간:** 1~3분 (인터넷 속도에 따라 다름)
- **정상:** 글자가 쭉 올라가다가 마지막 즈음 `Done` 이라는 단어가 보이고 프롬프트(`PS …>`)가 다시 나타납니다. 노란 `WARN` 줄은 경고일 뿐이라 무시해도 됩니다.
- **실패:** 빨간 `ERR` 또는 `ERROR` 가 보이고 멈춥니다. 아래 [자주 나는 오류](#6-자주-나는-오류와-해결법)를 보세요.

## 4. 쇼핑몰 켜기 (`pnpm dev`)

```powershell
pnpm dev
```

- **뜻:** 쇼핑몰을 **내 컴퓨터에서 연습용으로 켭니다**(개발 서버). 코드를 고치면 화면이 바로 바뀝니다.
- **정상:** 몇 초 뒤 이런 글자가 보입니다.

  ```
  ▲ Next.js 16.4.6 (Turbopack)
  - Local:         http://localhost:3000
  ✓ Ready in 564ms
  ```

- **그다음:** 브라우저(크롬·엣지)에서 **http://localhost:3000** 을 엽니다. 자동으로 한국어 화면(`/ko`)으로 이동합니다.
  - 처음 여는 페이지는 준비하느라 **5~20초** 걸릴 수 있습니다. 두 번째부터는 빠릅니다.
  - `localhost` 는 "내 컴퓨터 자신"이라는 뜻이라, **다른 사람은 이 주소로 들어올 수 없습니다.**
- **켜져 있는 동안:** 이 터미널 창은 **닫지 말고 그대로 두세요.** 창을 닫으면 쇼핑몰도 꺼집니다. 화면을 보는 동안 터미널에 글자가 계속 올라오는 것은 정상입니다(방문 기록).
- **데모 계정으로 로그인:** 로그인 화면 아래의 **"이 계정으로 채우기"** 버튼을 누르면 관리자·고객 계정이 자동으로 채워집니다.

### 쇼핑몰 끄기

- 켜 둔 터미널 창을 클릭하고 **Ctrl+C** 를 누릅니다. 프롬프트(`PS …>`)가 다시 나오면 꺼진 것입니다.
- 또는 그냥 터미널 창을 닫아도 됩니다.
- **데모 모드에서는 끄면 데이터가 처음으로 돌아갑니다.** 주문·가입·장바구니가 사라지고 상품 24개만 남습니다. 정상입니다.

### 데모 모드에서 바뀌는 것

외부 서비스 키를 넣으면 진짜 서비스로 하나씩 바뀝니다. 방법은 [외부 서비스 연결 체크리스트](SETUP_CHECKLIST.md).

| 기능           | 지금(키 없음)                               | 키를 넣으면                       |
| -------------- | ------------------------------------------- | --------------------------------- |
| 상품·주문 저장 | 컴퓨터 메모리에 임시 저장 (**끄면 초기화**) | Supabase 데이터베이스에 영구 저장 |
| 로그인         | 데모 계정 2개 + 직접 가입                   | Supabase 로그인                   |
| 결제           | "모의 결제" 버튼 (돈 안 나감)               | 토스페이먼츠 테스트 결제 화면     |
| 주문 확인 메일 | 보내지 않고 터미널에 글자로 출력            | Resend 로 실제 메일 발송          |
| 요청 횟수 제한 | 컴퓨터 메모리로 처리                        | Upstash Redis                     |
| 상품 이미지    | 관리자 화면에서 이미지 주소를 직접 입력     | 파일을 골라 업로드                |
| 새 주문 알림   | 관리자 대시보드가 30초마다 새로고침         | 주문 즉시 알림                    |

## 5. 그 밖의 명령어

모두 **2단계(폴더 이동)를 한 터미널에서** 입력합니다. 쇼핑몰이 켜져 있는 창은 쓰고 있으니, 새 터미널 창을 하나 더 열어서 하세요.

### 자주 쓸 수 있는 것

| 명령어          | 뜻 (언제 쓰나)                                                                                          | 걸리는 시간 | 정상일 때                          |
| --------------- | ------------------------------------------------------------------------------------------------------- | ----------- | ---------------------------------- |
| `pnpm dev`      | 쇼핑몰 켜기 (위 4단계)                                                                                  | 몇 초       | `Ready` 와 `http://localhost:3000` |
| `pnpm test`     | **규칙 검사 20개** 실행. 가격 계산·재고 차감·결제 중복 방지 같은 규칙이 맞는지 확인                     | 몇 초       | `Tests  20 passed (20)`            |
| `pnpm test:e2e` | **브라우저 자동 조작 검사 4개.** 크롬이 몰래 켜져서 손님처럼 담기→주문→결제→취소, 관리자 발송까지 해 봄 | 2~4분       | `4 passed`                         |

- `pnpm test:e2e` 는 설치된 **크롬**을 쓰고, 운영용으로 포장(빌드)한 뒤 검사용 쇼핑몰을 **3100번 포트**에 따로 켭니다. 포장 파일이 꼬이지 않도록, 켜 둔 `pnpm dev` 는 **끄고** 실행하는 것을 권합니다.
- 검사 중 `[csp-report]` 로 시작하는 긴 줄이 여러 번 나와도 정상입니다(보안 규칙 "보고만" 모드의 기록).

### 개발자가 주로 쓰는 것 (참고만)

직접 실행할 일은 거의 없습니다. 제가 작업을 마칠 때 이 검사들을 돌리고 결과를 알려 드립니다.

| 명령어                  | 뜻                                                                                                                                      |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm lint`             | 코드의 흔한 실수를 찾는 검사. 아무 말 없이 끝나면 통과                                                                                  |
| `pnpm format`           | 코드 줄 맞춤을 자동 정리 (파일 내용이 바뀜)                                                                                             |
| `pnpm format:check`     | 줄 맞춤이 돼 있는지 **확인만** (바꾸지 않음)                                                                                            |
| `pnpm typecheck`        | 데이터 모양 실수 검사. 아무 오류 없이 끝나면 통과                                                                                       |
| `pnpm build`            | 운영용으로 포장. 1~3분. 마지막에 화면 목록 표가 나오면 성공                                                                             |
| `pnpm start`            | `pnpm build` 로 포장한 것을 실행 (실제 인터넷 운영과 같은 방식)                                                                         |
| `pnpm audit:ci`         | 쓰고 있는 부품에 **알려진 보안 문제**가 있는지 확인                                                                                     |
| `pnpm gen:placeholders` | 상품 임시 그림(`public/products/*.svg`)을 다시 만들기                                                                                   |
| `pnpm db:push`          | Supabase 에 DB 설계도 적용. **Supabase 연결 후에만** ([체크리스트 2단계](SETUP_CHECKLIST.md#2-supabase-데이터베이스로그인이미지실시간)) |
| `pnpm db:types`         | Supabase 의 실제 DB 모양으로 코드 쪽 설명서 다시 만들기 (Supabase 연결 후)                                                              |
| `pnpm db:setup`         | Supabase 에 표·규칙·데모 상품 한 번에 설치 (`.env.local` 에 `SUPABASE_DB_URL` 필요, 이미 설치돼 있으면 그대로 둠)                       |
| `pnpm db:demo-users`    | Supabase 에 데모 계정 2개 만들기 (Supabase 연결 후)                                                                                     |
| `pnpm db:seed-sql`      | 데모 상품 목록으로 `supabase/seed.sql` 다시 만들기                                                                                      |

## 6. 자주 나는 오류와 해결법

| 화면에 보이는 글자 (일부)                                                                           | 뜻과 해결법                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `'pnpm' 용어가 cmdlet, 함수, 스크립트 파일 또는 실행할 수 있는 프로그램 이름으로 인식되지 않습니다` | 컴퓨터가 pnpm 을 못 찾는 상태. **가장 흔한 원인은 pnpm 을 설치하기 전에 열어 둔 창을 그대로 쓴 것**입니다(창은 열릴 때의 설정을 기억하기 때문). 순서대로: ① 열려 있는 PowerShell·터미널 창을 **모두 닫고**, VS Code 안의 터미널이었다면 VS Code 도 완전히 껐다 켭니다 ② 새 PowerShell 창에서 `pnpm --version` 입력 → `12.21.0` 같은 숫자가 나오면 해결 ③ 그래도 같으면 `node --version` 입력 → `v24…` 같은 숫자가 안 나오면 nodejs.org 에서 Node.js LTS 를 설치 ④ 숫자가 나오면 `npm install -g pnpm` 입력(pnpm 다시 설치, 1분 정도) 후 창을 닫고 새로 열기. _(지금 이 PC 에는 Node 24.22.1 과 pnpm 12.21.0 이 설치되어 있고, 새 창에서 정상 동작을 확인했습니다)_ |
| `이 시스템에서 스크립트를 실행할 수 없으므로 …pnpm.ps1 파일을 로드할 수 없습니다`                   | Windows 보안 설정이 PowerShell 에서 pnpm 실행을 막는 상태. 직접 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` 를 입력하고 `Y` 로 답하면 **내 계정에서만** 풀립니다. 또는 `pnpm` 대신 `pnpm.cmd` 라고 쳐도 됩니다(예: `pnpm.cmd dev`). PowerShell 대신 "명령 프롬프트(cmd)"를 열어 같은 명령을 입력해도 됩니다. _(지금 이 PC 는 이미 풀려 있습니다)_                                                                                                                                                                                                                                                                                                        |
| `ERR_PNPM_NO_PKG_MANIFEST` 또는 `No package.json … found`                                           | **프로젝트 폴더가 아닌 곳**에서 명령을 쳤습니다. 2단계 `cd …chanhee-mall` 부터 다시 하세요                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `Port 3000 is in use` (그리고 3001 같은 다른 번호로 켜짐)                                           | 3000번 방을 다른 프로그램(대개 **이미 켜 둔 쇼핑몰**)이 쓰고 있어서 3001번으로 켜졌다는 뜻. 화면에 나온 `Local:` 주소(예: `http://localhost:3001`)로 들어가거나, 먼저 켜 둔 창을 찾아 Ctrl+C 로 끄고 다시 켜세요                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `EPERM: operation not permitted` 또는 `EBUSY: resource busy`                                        | 다른 프로그램이 파일을 붙잡고 있는 상태. 이 프로젝트는 **OneDrive 폴더 안**에 있어서, OneDrive 가 파일을 올리는 중일 때 자주 생깁니다. 작업 표시줄의 구름 아이콘 → 설정 → **동기화 일시 중지** 후 다시 시도하세요. 켜 둔 쇼핑몰(다른 터미널 창)이 있다면 그것도 끄고 하세요                                                                                                                                                                                                                                                                                                                                                                                        |
| `Cannot find module …` 또는 화면에 `Module not found`                                               | 부품이 빠진 상태. `pnpm install` 을 다시 실행하세요                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 브라우저에 `사이트에 연결할 수 없음` / `ERR_CONNECTION_REFUSED`                                     | 쇼핑몰이 꺼져 있습니다. 4단계 `pnpm dev` 를 실행하고 `Ready` 가 보인 뒤에 다시 여세요                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 브라우저에 빨간 오류 화면 (`Unhandled Runtime Error` 등)                                            | 코드 오류입니다. **화면 캡처와 터미널의 빨간 글자를 복사해서** 저에게 보내 주세요                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `환경변수 형식 오류` 또는 `Supabase 환경변수가 비어 있습니다`                                       | `.env.local` 에 넣은 값이 잘못됐습니다. 특히 토스 키는 `test_` 로 시작해야 합니다(실제 결제 키 실수를 막는 장치). 값을 확인하거나, 잠시 그 줄을 지우고 데모 모드로 켜세요                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

그래도 안 되면, **터미널 화면 전체를 복사**(마우스로 드래그해서 선택 → Enter)해서 보내 주세요. 빨간 글자 몇 줄이면 원인을 대부분 찾을 수 있습니다.

## 7. 주요 화면 주소

쇼핑몰을 켠 상태에서 브라우저 주소창에 입력합니다. `/ko` 를 `/en` 으로 바꾸면 영어 화면입니다(머리글의 언어 버튼과 같음).

| 화면              | 주소                                                         |
| ----------------- | ------------------------------------------------------------ |
| 홈                | http://localhost:3000/ko                                     |
| 상품 목록·검색    | http://localhost:3000/ko/products                            |
| 상품 상세 (예시)  | http://localhost:3000/ko/products/stainless-tumbler          |
| 장바구니          | http://localhost:3000/ko/cart                                |
| 주문 내역         | http://localhost:3000/ko/orders (로그인 필요)                |
| 관리자            | http://localhost:3000/ko/admin (관리자 계정으로 로그인 필요) |
| 관리자: 상품·주문 | `/ko/admin/products`, `/ko/admin/orders`                     |
| 상태 확인         | http://localhost:3000/api/health → `"ok":true` 면 정상       |

주문 흐름: 장바구니 → 주문서(`/ko/checkout`, 배송지 입력) → 결제 화면 → 결제 완료 또는 실패 화면 → 주문 내역

## 8. 폴더 구조: 어디에 무엇이 있나

프로젝트 폴더를 열면 많은 파일이 보이지만, 볼 만한 곳은 몇 군데뿐입니다.

| 폴더 / 파일                   | 무엇이 들어 있나                                                              | 직접 열어 볼 일  |
| ----------------------------- | ----------------------------------------------------------------------------- | ---------------- |
| `docs/`                       | **안내 문서들** (이 문서, 코드 리뷰 안내서, 체크리스트, 장애 대응, 용어 사전) | 자주             |
| `README.md`                   | 프로젝트 첫 소개와 문서 목록                                                  | 가끔             |
| `messages/ko.json`, `en.json` | **화면 문구** (한국어·영어). 버튼 글자 등을 바꾸고 싶을 때                    | 가끔             |
| `src/`                        | **쇼핑몰 코드 전부**. 아래 표 참고                                            | 리뷰할 때        |
| `supabase/`                   | 데이터베이스 설계도(`migrations/`)와 기본 상품 데이터(`seed.sql`)             | Supabase 연결 때 |
| `public/`                     | 그림 파일 (상품 임시 그림 등)                                                 | 거의 없음        |
| `tests/`                      | 자동 검사 (`unit/` 규칙 검사, `e2e/` 브라우저 검사)                           | 거의 없음        |
| `scripts/`                    | 보조 작업 프로그램 (데모 계정 만들기, 임시 그림 만들기 등)                    | 거의 없음        |
| `.github/`                    | GitHub 자동 검사·매일 깨우기·보안 알림 설정                                   | 거의 없음        |
| `.env.example`                | 외부 서비스 키를 적는 **빈 양식**                                             | 연결할 때        |
| `.env.local`                  | 실제 키를 적는 파일. **지금은 없음**(데모 모드). GitHub 에 올라가지 않음      | 연결할 때        |
| `package.json`                | 쓰는 부품 목록과 명령어(`scripts`) 목록                                       | 거의 없음        |
| `node_modules/`               | 내려받은 부품. 아주 크고, 열어 볼 필요 없음                                   | 없음             |
| `.next/`                      | 쇼핑몰을 켤 때 자동으로 생기는 임시 파일. 지워도 다시 생김                    | 없음             |

### `src/` 안쪽

| 폴더                  | 무엇인가                                                                                                     |
| --------------------- | ------------------------------------------------------------------------------------------------------------ |
| `src/app/[locale]/`   | **화면(페이지)**. 폴더 이름이 곧 주소입니다. 예) `products/` = `/ko/products`. `admin/` 은 관리자 화면       |
| `src/app/api/`        | 화면 없이 데이터만 주고받는 서버 창구 (결제 완료 처리, 토스 알림 받기, 예약 작업, 상태 확인)                 |
| `src/components/`     | 화면을 이루는 **부품** (머리글, 상품 카드, 장바구니 등). `ui/` 는 버튼·입력칸 같은 기본 부품                 |
| `src/server/`         | **서버에서만 도는 핵심 로직**. 주문·결제 규칙(`orders.ts`), 로그인(`auth.ts`), 토스 연결(`payments/toss.ts`) |
| `src/server/repo/`    | 데이터 저장 담당. `memory.ts`(데모 모드) / `supabase.ts`(실제 DB) 두 가지가 같은 방식으로 동작               |
| `src/server/actions/` | 화면의 버튼이 부르는 서버 기능 (모든 입력을 서버에서 다시 검사)                                              |
| `src/lib/`            | 가격 계산 규칙, 입력 검사 규칙 같은 **공통 규칙**                                                            |
| `src/stores/`         | 브라우저 쪽 임시 기억 (장바구니 개수 표시 등)                                                                |

코드를 어떤 순서로 읽으면 되는지는 [코드 리뷰 안내서](REVIEW_GUIDE.md)에 정리해 두었습니다.

## 9. 이 쇼핑몰의 안전장치 (요약)

코드를 읽지 않아도 알아 두면 좋은 것들입니다.

- **결제 금액 조작 방지:** 화면(브라우저)이 보낸 금액을 믿지 않고, 서버가 DB 가격으로 다시 계산해서 토스 승인 전에 비교합니다.
- **중복 결제 방지:** 같은 결제 승인이 두 번 와도 한 번만 반영됩니다.
- **결제 안 한 주문 정리:** 30분 동안 결제하지 않은 주문은 자동으로 취소되고 재고가 돌아옵니다.
- **토스 알림 재확인:** 토스가 보낸 알림(웹훅) 내용을 그대로 믿지 않고, 토스에 결제 상태를 다시 물어봅니다.
- **이중 권한 검사:** 데이터베이스 규칙(RLS)과 서버 코드 양쪽에서 "이 사람이 이걸 볼/바꿀 수 있나"를 확인합니다.
- **실제 결제 키 실수 방지:** 토스 키가 `test_` 로 시작하지 않으면 쇼핑몰이 아예 켜지지 않습니다.
- **반복 공격 방지:** 로그인·결제·검색을 짧은 시간에 너무 많이 하면 잠시 막습니다.
