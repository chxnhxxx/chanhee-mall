# 용어 사전 (비개발자용)

안내 문서에 나오는 개발 용어를 쉬운 말로 풀었습니다. 문서를 읽다가 모르는 말이 나오면 여기서 찾아보세요. `Ctrl+F` 를 누르고 단어를 입력하면 바로 찾을 수 있습니다.

---

## 1. 컴퓨터와 명령어

| 용어                         | 쉬운 뜻                                                                                                                                                                                                             |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 터미널                       | 마우스 대신 **글자로 컴퓨터에 지시하는 창**입니다. 검은(또는 파란) 창에 명령어를 치고 Enter 를 누릅니다. Windows 에서는 "PowerShell"이 터미널입니다. 여는 법은 [실행·구조 안내](RUN_GUIDE.md#1-터미널-여는-법) 참고 |
| 명령어                       | 터미널에 치는 한 줄짜리 지시. 예) `pnpm dev` = "쇼핑몰 켜 줘"                                                                                                                                                       |
| 폴더 이동 (`cd`)             | `cd 폴더경로` = "이 폴더로 들어가서 일해". 명령어는 **지금 있는 폴더 기준**으로 동작하므로, 대부분 먼저 프로젝트 폴더로 이동해야 합니다                                                                             |
| 프롬프트                     | 터미널에서 명령을 기다리는 줄. `PS C:\Users\(내 이름)>` 처럼 보이며, `>` 앞이 지금 있는 폴더입니다                                                                                                                      |
| Ctrl+C (터미널에서)          | 터미널에서는 "복사"가 아니라 **지금 실행 중인 일을 멈춤**입니다. 쇼핑몰을 끌 때 씁니다                                                                                                                              |
| 경로                         | 파일이 있는 위치를 적은 주소. 예) `~\OneDrive\Desktop\claude\chanhee-mall\docs`                                                                                                                        |
| 프로젝트 폴더                | 이 쇼핑몰의 모든 파일이 들어 있는 폴더: `~\OneDrive\Desktop\claude\chanhee-mall`                                                                                                                       |
| 설치 / 내려받기              | 인터넷에서 프로그램이나 부품을 받아 컴퓨터에 넣는 것                                                                                                                                                                |
| Node.js (노드)               | 이 쇼핑몰 프로그램을 **돌리는 엔진**. 이게 깔려 있어야 쇼핑몰을 켤 수 있습니다                                                                                                                                      |
| pnpm                         | 쇼핑몰에 필요한 **부품을 내려받고, 정해진 작업을 실행해 주는 관리 도구**. `pnpm 작업이름` 형태로 씁니다                                                                                                             |
| 패키지 / 라이브러리 / 의존성 | 남이 만들어 공개한 **코드 부품**. 이 쇼핑몰은 수백 개의 부품을 가져다 씁니다. `node_modules` 폴더에 들어갑니다                                                                                                      |
| `node_modules` 폴더          | 내려받은 부품이 모이는 폴더. 아주 크고, 직접 열어 볼 필요 없습니다. 지워도 `pnpm install` 로 다시 생깁니다                                                                                                          |
| 스크립트 (`package.json`)    | 자주 쓰는 작업에 붙인 별명. `pnpm dev`, `pnpm test` 같은 것들이 `package.json` 의 `scripts` 에 적혀 있습니다                                                                                                        |
| localhost                    | "**내 컴퓨터 자신**"을 뜻하는 주소. `http://localhost:3000` 은 내 컴퓨터에서 켜 둔 쇼핑몰입니다. 다른 사람은 이 주소로 들어올 수 없습니다                                                                           |
| 포트 (3000, 3100)            | 한 컴퓨터 안에서 프로그램을 구분하는 **방 번호**. 주소 끝의 `:3000` 이 포트입니다                                                                                                                                   |

## 2. 쇼핑몰을 만들고 검사하는 일

| 용어                         | 쉬운 뜻                                                                                                     |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 개발 서버 (`pnpm dev`)       | 내 컴퓨터에서 쇼핑몰을 **연습용으로 켜 둔 상태**. 코드를 고치면 화면이 바로 바뀝니다                        |
| 빌드 (`pnpm build`)          | 코드를 **실제 운영용으로 포장**하는 작업. 몇 분 걸리고, 문제가 있으면 여기서 멈춥니다                       |
| 데모 모드                    | 외부 서비스 가입 없이도 쇼핑몰이 전부 동작하도록 **흉내 내는 상태**. 데이터는 껐다 켜면 처음으로 돌아갑니다 |
| 모의 결제                    | 실제 결제 대신 "결제된 척" 하는 버튼. 데모 모드에서만 보입니다                                              |
| 테스트                       | 프로그램이 제대로 동작하는지 **자동으로 확인하는 검사**. 사람이 매번 눌러 볼 필요가 없습니다                |
| 단위 테스트 (`pnpm test`)    | 가격 계산, 재고 차감 같은 **규칙 하나하나를 확인**하는 빠른 검사 (20개, 몇 초)                              |
| E2E 테스트                   | 실제 브라우저를 **자동으로 조작해서 손님처럼 처음부터 끝까지** 써 보는 검사 (4개, 1~3분)                    |
| 린트 (`pnpm lint`)           | 코드의 **흔한 실수와 나쁜 습관을 찾아 주는 맞춤법 검사기** 같은 것                                          |
| 포맷 (`pnpm format`)         | 코드의 **줄 맞춤·띄어쓰기를 자동으로 정리**                                                                 |
| 타입 검사 (`pnpm typecheck`) | "숫자 자리에 글자가 들어갔다" 같은 **데이터 모양 실수를 찾는 검사**                                         |
| 오류 / 에러                  | 프로그램이 하려던 일을 못 했다는 신호. 빨간 글씨로 나오는 경우가 많습니다                                   |
| 로그                         | 프로그램이 **무엇을 했는지 적어 두는 기록**. 오류가 나면 로그를 보고 원인을 찾습니다                        |

## 3. 코드 보관과 배포

| 용어                | 쉬운 뜻                                                                                                    |
| ------------------- | ---------------------------------------------------------------------------------------------------------- |
| git (깃)            | 코드의 **변경 이력을 저장하는 도구**. "언제 무엇을 바꿨는지" 전부 기록되어, 예전 상태로 되돌릴 수 있습니다 |
| 커밋 (commit)       | 지금까지의 변경을 **한 묶음으로 저장**한 것. 게임의 세이브 포인트와 비슷합니다                             |
| 브랜치 (branch)     | 같은 코드의 **갈래**. 기본 갈래 이름은 `main`                                                              |
| GitHub (깃허브)     | git 기록을 **인터넷에 보관하는 서비스**. 백업 겸 자동 검사·배포의 출발점                                   |
| 저장소 (repository) | GitHub 에 올린 **프로젝트 하나**의 보관함                                                                  |
| 푸시 (push)         | 내 컴퓨터의 커밋을 **GitHub 로 올리는 것**                                                                 |
| private 저장소      | 나만 볼 수 있는 비공개 보관함                                                                              |
| CI                  | GitHub 에 코드를 올릴 때마다 **자동으로 검사를 돌리는 것**. 결과가 초록불(통과)·빨간불(실패)로 표시됩니다  |
| GitHub Actions      | GitHub 의 자동 작업 기능. CI 와 매일 사이트 깨우기가 이걸로 돌아갑니다 (`.github/workflows` 폴더)          |
| Dependabot          | 쓰고 있는 부품에 **보안 문제가 알려지면 알려 주고, 업데이트를 제안**하는 GitHub 기능                       |
| 배포 (deploy)       | 쇼핑몰을 **인터넷에 올려서 누구나 접속할 수 있게** 하는 것                                                 |
| Vercel (버셀)       | 이 쇼핑몰을 인터넷에 올려 주는 **호스팅 서비스**. GitHub 에 올리면 자동으로 배포합니다                     |
| 미리보기 배포       | 정식 주소와 별개로 **확인용 임시 주소**에 올리는 배포                                                      |
| 롤백                | 문제가 생긴 배포를 **직전의 정상 버전으로 되돌리는 것**                                                    |
| 도메인              | `chanhee-mall.com` 같은 **사이트 이름 주소**. 지금은 없고, Vercel 이 주는 `…vercel.app` 주소를 씁니다      |

## 4. 설정값과 키

| 용어                | 쉬운 뜻                                                                                                                                                                     |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 환경변수            | 코드 밖에 따로 적어 두는 **설정값과 비밀 열쇠**. `이름=값` 한 줄씩 적습니다. 예) `TOSS_SECRET_KEY=test_sk_...`                                                              |
| `.env.local` 파일   | 내 컴퓨터에서 쓰는 환경변수를 적는 파일. **비밀이 들어가므로 GitHub 에 올라가지 않게 막아 두었습니다**                                                                      |
| `.env.example` 파일 | `.env.local` 의 **빈 양식**. 어떤 값이 필요한지 이름만 적혀 있습니다. 이걸 복사해서 `.env.local` 을 만듭니다                                                                |
| API                 | 프로그램끼리 **정해진 방식으로 주고받는 창구**. 예) 우리 서버가 토스 API 에 "이 결제 승인해 줘"라고 요청                                                                    |
| API 키              | 외부 서비스가 "**당신이 누구인지**" 확인하는 열쇠. 서비스에 가입하면 발급됩니다                                                                                             |
| 공개 키 / 비밀 키   | 공개 키는 화면(브라우저)에 들어가도 되는 키, 비밀 키는 **절대 화면이나 GitHub 에 노출되면 안 되는 키**. 이 프로젝트에서는 이름이 `NEXT_PUBLIC_` 으로 시작하면 공개 키입니다 |
| 테스트 키 (`test_`) | 진짜 돈이 오가지 않는 **연습용 결제 키**. 이 쇼핑몰은 `test_` 로 시작하지 않는 토스 키를 넣으면 일부러 켜지지 않습니다                                                      |
| 시크릿 (Secret)     | GitHub·Vercel 에 저장하는 비밀값. 저장 후에는 다시 볼 수 없고 덮어쓰기만 됩니다                                                                                             |
| 대시보드 / 콘솔     | 외부 서비스 웹사이트의 **관리 화면**                                                                                                                                        |
| 리전                | 서버가 실제로 있는 **지역**. 한국 손님이면 서울(Seoul)이나 도쿄에 가까울수록 빠릅니다                                                                                       |
| 무료 플랜 / Hobby   | 서비스의 무료 요금제. 사용량 한도가 있습니다                                                                                                                                |

## 5. 쇼핑몰 안쪽 구조

| 용어                  | 쉬운 뜻                                                                                             |
| --------------------- | --------------------------------------------------------------------------------------------------- |
| 서버 / 브라우저       | 서버 = 보이지 않는 곳에서 주문·결제를 처리하는 쪽. 브라우저 = 손님이 보는 화면 쪽(조작될 수 있음)   |
| DB (데이터베이스)     | 상품·주문·회원 정보를 저장하는 곳. 엑셀 파일과 비슷합니다                                           |
| 테이블 / 행           | 테이블 = 엑셀의 시트(예: 주문 시트), 행 = 한 줄(주문 하나)                                          |
| SQL                   | DB 에게 일을 시키는 **전용 언어**                                                                   |
| 마이그레이션          | DB 의 **설계도(시트와 칸 만들기)를 순서대로 적은 SQL 파일**. `supabase/migrations` 폴더             |
| 시드 (seed)           | 처음에 넣어 두는 **기본 데이터** (데모 상품 24개 등)                                                |
| RLS                   | DB 가 직접 "**이 사람이 이 줄을 볼 수 있나**"를 판단하는 보안 규칙. 남의 주문을 못 보게 막습니다    |
| Supabase (수파베이스) | DB·로그인·이미지 저장·실시간 알림을 한 번에 제공하는 서비스                                         |
| 토스페이먼츠          | 카드 결제를 처리해 주는 결제 서비스. 지금은 테스트 모드만 씁니다                                    |
| 결제위젯              | 토스가 제공하는 **결제 화면 부품**. 우리 결제 페이지 안에 끼워 넣습니다                             |
| 웹훅                  | 다른 서비스(토스)가 "**무슨 일이 생겼어**"라고 우리 서버에 먼저 알려 주는 연락                      |
| Resend (리센드)       | 주문 확인 **메일 발송** 서비스                                                                      |
| Upstash Redis         | 아주 빠른 **임시 메모장** 서비스. 여기서는 "1분에 너무 많은 요청" 막기에 씁니다                     |
| 레이트 리밋           | 짧은 시간에 너무 많은 요청(로그인 시도 반복 등)을 **막는 장치**                                     |
| Sentry (센트리)       | 사이트에서 오류가 나면 **자동으로 모아서 알려 주는** 서비스                                         |
| GA4                   | 구글 애널리틱스. **방문자 수·구매 수를 세는** 분석 서비스                                           |
| 예약 작업 (cron)      | "5분마다 이걸 해" 같은 **정해진 시간마다 자동으로 하는 일**. 예) 30분 지난 결제 대기 주문 자동 취소 |
| 큐 (queue)            | 나중에 처리할 일을 **줄 세워 두는 대기열**. 예) 실패한 메일을 모아 두었다가 다시 보내기             |
| CSP                   | 우리가 허락한 곳의 프로그램만 화면에서 실행되게 하는 **브라우저 보안 규칙**                         |
| HTTPS / HSTS          | 주소창 자물쇠(암호화 통신) / "이 사이트는 항상 자물쇠로만 접속해"라고 브라우저에 알려 주는 설정     |
| 캐시                  | 자주 쓰는 결과를 잠깐 저장해 두고 빠르게 꺼내 쓰는 것                                               |
| 세션 / 쿠키           | 로그인 상태를 기억하는 출입증 / 브라우저에 저장되는 작은 메모                                       |

## 6. 문서에 나오는 표시

| 표시                     | 뜻                                                                                                         |
| ------------------------ | ---------------------------------------------------------------------------------------------------------- |
| `[미확인]`               | 실제 서비스나 공식 문서로 **아직 확인하지 못한 부분**. 해당 단계에서 직접 확인이 필요합니다                |
| `- [ ]`                  | 체크 칸. 끝낸 항목은 `- [x]` 로 바꿔 두면 진행 상황을 볼 수 있습니다                                       |
| `<프로젝트ID>` 같은 꺾쇠 | **내 값으로 바꿔 넣으라는 자리**. 꺾쇠 `< >` 는 빼고 입력합니다                                            |
| 회색 상자 안 글자        | 그대로 복사해서 터미널에 붙여 넣는 명령어. 터미널에서 붙여 넣기는 **마우스 오른쪽 클릭**이 가장 확실합니다 |
