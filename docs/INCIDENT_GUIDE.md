# 운영 장애 대응 안내 (비개발자용)

쇼핑몰을 인터넷에 올린(배포한) 뒤 **문제가 생겼을 때 무엇부터 확인하고 어떻게 대처하는지** 정리한 문서입니다.

- 지금은 내 컴퓨터에서만 켜는 데모 상태라, 대부분 **배포 후([체크리스트 9단계](SETUP_CHECKLIST.md#9-vercel-배포-인터넷에-올리기))에 해당**합니다. 내 컴퓨터에서 켜다가 생기는 문제는 [실행·구조 안내의 자주 나는 오류](RUN_GUIDE.md#6-자주-나는-오류와-해결법)를 보세요.
- 모르는 말은 [용어 사전](GLOSSARY.md)을 보세요.
- `[미확인]` 은 실제 서비스로 확인하지 못한 부분입니다.

**가장 중요한 원칙 세 가지**

1. **당황해서 이것저것 바꾸지 않기.** 하나 바꿀 때마다 무엇을 바꿨는지 메모하세요. 동시에 여러 개를 바꾸면 무엇이 원인이었는지 알 수 없습니다.
2. **최근에 바꾼 게 있으면 그것부터 의심하기.** 새로 배포한 직후에 문제가 생겼다면, 먼저 [직전 버전으로 되돌리기](#3-직전-버전으로-되돌리기-롤백)가 가장 빠릅니다.
3. **돈이 걸린 문제(결제·환불)가 최우선.** 화면이 조금 깨진 것보다 결제가 안 되거나 두 번 되는 것이 훨씬 급합니다.

## 1. 문제가 생기면 처음 5분

순서대로 확인하고, 각 결과를 메모해 두세요. 저에게 알려 주실 때 그대로 쓰면 됩니다.

| 순서 | 확인할 것                    | 어떻게                                                                                                                        |
| ---- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 1    | **나만 그런가?**             | 휴대폰 데이터(와이파이 끄기)나 다른 브라우저, 시크릿 창으로 접속해 봅니다. 나만 안 되면 내 인터넷·브라우저 문제일 수 있습니다 |
| 2    | **쇼핑몰 상태 확인 주소**    | `https://<배포 주소>/api/health` 를 엽니다. 아래 표로 판단                                                                    |
| 3    | **외부 서비스가 고장 났나?** | [서비스 상태 페이지](#5-서비스-상태-페이지와-관리-화면)에서 Vercel·Supabase 등에 빨간 표시가 있는지                           |
| 4    | **최근에 무엇을 바꿨나?**    | 마지막 배포 시간(Vercel → Deployments), 마지막으로 바꾼 설정값                                                                |
| 5    | **오류 기록**                | Sentry(오류 자동 수집)와 Vercel Logs(서버 기록)에서 빨간 줄 확인. 방법은 [4장](#4-오류-기록-보는-법)                          |

**상태 확인 주소(`/api/health`) 결과 읽는 법**

| 보이는 것                                         | 뜻                                                                                                                            |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `{"ok":true,"backend":"supabase", …}`             | 쇼핑몰과 데이터베이스 모두 정상. 문제는 특정 기능(결제, 메일 등) 쪽                                                           |
| `{"ok":true,"backend":"memory", …}`               | 데이터베이스 키가 빠져 **데모 모드로 돌고 있음**. Vercel 환경변수 확인 ([2-H](#h-주문상품이-사라졌다--데모-모드로-돌고-있다)) |
| `{"ok":false, …}` (오류 503)                      | 쇼핑몰은 켜져 있지만 **데이터베이스에 연결 못 함** ([2-B](#b-화면은-나오는데-상품이-안-보이거나-오류-화면이-뜬다))            |
| 아무것도 안 뜸 / `404` / `500` / Vercel 오류 화면 | 쇼핑몰 자체가 안 뜸 ([2-A](#a-사이트가-아예-안-열린다))                                                                       |

## 2. 증상별 대응

### A. 사이트가 아예 안 열린다

1. [Vercel 상태 페이지](https://www.vercel-status.com)에 장애 표시가 있으면 → Vercel 이 고칠 때까지 기다립니다. 우리가 할 일은 없습니다.
2. Vercel → 프로젝트 → **Deployments**: 맨 위 배포가 빨간 **Error** 면 새 버전 포장(빌드)에 실패한 것입니다. 이 경우 Vercel 은 보통 **이전 정상 버전을 계속 보여 주므로**, 사이트가 안 열리는 원인은 다른 데 있을 가능성이 큽니다. [미확인] 첫 배포가 실패한 경우는 보여 줄 이전 버전이 없습니다.
3. 맨 위 배포가 **Ready** 인데 안 열리면 → 직전 배포 이후 생긴 문제일 수 있으니 [직전 버전으로 되돌리기](#3-직전-버전으로-되돌리기-롤백).
4. 그래도 안 되면 저에게 Deployments 화면과 오류 화면 캡처를 보내 주세요.

### B. 화면은 나오는데 상품이 안 보이거나 오류 화면이 뜬다

대개 **데이터베이스(Supabase) 연결 문제**입니다.

1. [Supabase 상태 페이지](https://status.supabase.com) 확인
2. Supabase 대시보드에 들어가 프로젝트가 **Paused(일시정지)** 상태인지 확인
   - 무료 플랜은 **7일 동안 사용이 없으면 잠듭니다.** 매일 자동으로 깨우는 장치(GitHub 의 `keepalive`)를 넣어 두었지만, `SITE_URL` 시크릿이 없거나 GitHub Actions 가 꺼져 있으면 동작하지 않습니다.
   - 잠들었다면 대시보드의 **Restore project** 버튼으로 깨웁니다. 몇 분 걸립니다. 데이터는 남아 있습니다. [미확인] 장기간 방치 시 복구 가능 기한은 Supabase 정책 확인
   - 다시 잠들지 않게 [체크리스트 1단계](SETUP_CHECKLIST.md#1-github-저장소-코드-보관--자동-검사)의 `SITE_URL` 설정과 GitHub **Actions** 탭의 `keepalive` 가 초록불인지 확인
3. 최근에 Supabase 키를 바꿨다면 Vercel 환경변수에도 같은 값이 들어 있는지 확인 → **Redeploy**
4. Supabase 무료 한도(저장 용량 등)를 넘었는지: Supabase → **Usage** 화면 확인

### C. 결제가 안 된다 (결제 화면이 안 뜨거나, 결제 승인이 실패)

**급한 일:** 손님 돈이 빠졌는지부터 확인합니다.

1. **토스 개발자센터 → 결제 내역**에서 해당 시간의 결제가 있는지, 상태가 무엇인지 확인
2. 쇼핑몰 **관리자 → 주문**에서 같은 주문의 상태 확인
3. 경우별 판단

   | 토스 결제 내역  | 쇼핑몰 주문 상태 | 뜻과 대처                                                                                                                                                                                                 |
   | --------------- | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | 없음            | 결제 대기        | 손님이 결제를 끝내지 않음. **아무것도 안 해도 30분 뒤 자동 취소**되고 재고도 돌아옵니다                                                                                                                   |
   | 승인 완료(DONE) | 결제 완료        | 정상                                                                                                                                                                                                      |
   | 승인 완료(DONE) | 결제 대기·취소됨 | **돈은 나갔는데 주문이 안 됨.** 토스 알림(웹훅)이 보정해 줄 수 있으니 몇 분 기다렸다가 다시 확인. 그래도 다르면 저에게 알려 주세요. 손님이 급하면 토스 개발자센터에서 그 결제를 **직접 취소(환불)**하세요 |
   | 없음 또는 실패  | 결제 완료        | 일어나면 안 되는 상황(쇼핑몰은 토스에 다시 물어본 뒤에만 결제 완료로 바꿈). **즉시 저에게 알려 주세요**                                                                                                   |

4. 결제 화면 자체가 안 뜨면
   - 최근에 `CSP_ENFORCE=1` 을 켰다면 → [2-G](#g-보안-규칙csp을-켠-뒤-결제우편번호-화면이-안-뜬다)
   - Vercel 환경변수의 토스 키 두 개(`NEXT_PUBLIC_TOSS_CLIENT_KEY`, `TOSS_SECRET_KEY`)가 있고 `test_` 로 시작하는지
   - [미확인] 토스 장애 공지는 토스페이먼츠 개발자센터에서 확인

**지금은 테스트 키만 쓰므로 진짜 돈은 오가지 않습니다.** 위 절차는 나중에 실제 결제로 바꿀 때를 대비한 것입니다.

### D. 주문 확인 메일이 안 온다

1. 먼저 **스팸함** 확인
2. 아직 내 도메인을 인증하지 않았다면, 모든 메일은 `EMAIL_DEV_REDIRECT_TO` 에 적은 **내 주소로만** 갑니다(손님에게는 안 감). 정상입니다.
3. Resend 대시보드 → **Logs/Emails** 에서 발송 기록과 실패 이유 확인
4. 실패한 메일은 대기열에 쌓였다가 **10분마다 다시 보냅니다.** 단, [체크리스트 2-5](SETUP_CHECKLIST.md#2-5-예약-작업-자동으로-정해진-시간마다-하는-일)의 메일 재시도 예약 작업을 켜 둔 경우에만입니다.
5. 메일이 안 가도 **주문과 결제는 정상 처리**됩니다. 급하지 않은 문제입니다.

### E. 로그인이 안 되거나 "요청이 너무 많습니다"가 뜬다

1. "요청이 너무 많습니다"는 반복 공격을 막는 장치입니다. 같은 사람이 **1분에 로그인 10번**, 검색 60번을 넘기면 잠시 막습니다. **1분 기다리면 풀립니다.**
2. 많은 손님이 동시에 이 안내를 본다면 공격이나 설정 문제일 수 있습니다. 저에게 알려 주세요.
3. 비밀번호가 맞는데 로그인이 안 되면: Supabase → **Authentication → Users** 에서 그 계정이 있는지 확인. 가입 확인 메일 설정("Confirm email")이 켜져 있으면 가입 직후 로그인이 안 됩니다([체크리스트 2-1](SETUP_CHECKLIST.md#2-1-가입과-키)).

### F. 새로 배포한 뒤부터 이상하다

가장 흔하고, 가장 쉽게 고칠 수 있는 경우입니다.

1. [직전 버전으로 되돌리기](#3-직전-버전으로-되돌리기-롤백) → 몇 초~1분이면 이전 상태로 돌아갑니다.
2. 사이트가 정상으로 돌아오면 급한 불은 끈 것입니다. 무엇이 문제였는지는 저와 함께 천천히 찾으면 됩니다.

### G. 보안 규칙(CSP)을 켠 뒤 결제·우편번호 화면이 안 뜬다

[체크리스트 10단계](SETUP_CHECKLIST.md#10-배포-후-보안-마무리)에서 `CSP_ENFORCE=1` 을 켜면, 허락 목록에 없는 외부 프로그램이 차단됩니다.

1. Vercel → **Settings → Environment Variables** 에서 `CSP_ENFORCE` 를 삭제 → **Redeploy**. 다시 "보고만" 모드로 돌아가 바로 정상화됩니다.
2. Vercel **Logs** 에서 `[csp-report]` 로 시작하는 줄을 복사해 저에게 보내 주시면, 허락 목록을 고쳐 다시 켤 수 있게 하겠습니다.

### H. 주문·상품이 사라졌다 / 데모 모드로 돌고 있다

1. `/api/health` 가 `"backend":"memory"` 면, 쇼핑몰이 데이터베이스 대신 **임시 메모리로 돌고 있는 것**입니다. 이 상태에서 받은 주문은 다음 재시작 때 사라집니다.
2. Vercel 환경변수에 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY` 세 개가 모두 있는지 확인 → **Redeploy**
3. Supabase 에 저장된 데이터 자체가 지워졌다면: Supabase → **Database → Backups** 확인. [미확인] 무료 플랜의 백업 보관·복구 범위는 Supabase 요금 정책 확인. 이 경우 직접 복구하지 말고 저에게 먼저 알려 주세요.

### I. 비밀 키가 새어 나간 것 같다

예) 실수로 키를 채팅·스크린샷·GitHub 에 올림, 모르는 결제나 메일 발송 기록이 보임.

**바로 할 일 (순서대로)**

1. 그 서비스에서 **키를 새로 발급**하고 **옛 키는 삭제/비활성화**합니다. 옛 키를 지우는 순간 그 키로는 아무것도 못 합니다.
   - Supabase: Project Settings → API Keys / 토스: 개발자센터 → API 키 / Resend·Upstash·Sentry: 각 API Keys 화면
2. 새 키를 Vercel 환경변수와 내 컴퓨터의 `.env.local` 에 넣고 → Vercel **Redeploy**
3. 키가 GitHub 에 올라갔다면 저에게 알려 주세요. 기록에서 지우는 것만으로는 부족하고, **키 교체(1~2번)가 진짜 해결**입니다.
4. 해당 서비스의 사용 기록을 보고 이상한 사용이 있었는지 확인

`SESSION_SECRET` 이나 `CRON_SECRET` 이 새었다면 [체크리스트 0-3](SETUP_CHECKLIST.md#0-3-envlocal-파일-만들기)의 명령으로 새 값을 만들어 바꾸면 됩니다. `SESSION_SECRET` 을 바꾸면 데모 모드 손님들은 다시 로그인해야 합니다.

### J. 이상한 주문이나 공격이 의심된다

예) 같은 사람이 짧은 시간에 주문을 수십 개, 처음 보는 관리자 계정.

1. 관리자 → 주문에서 해당 주문들을 캡처
2. Supabase → **Authentication → Users** 에서 의심 계정 확인. 관리자 권한이 있으면 안 되는 계정이 있다면 **즉시 저에게 알려 주세요**
3. 데모 관리자 계정 비밀번호는 공개되어 있습니다. 실제 데이터를 넣기 전에 반드시 바꾸세요([체크리스트 10단계](SETUP_CHECKLIST.md#10-배포-후-보안-마무리))

## 3. 직전 버전으로 되돌리기 (롤백)

새 배포 후 문제가 생겼을 때 가장 빠른 해결책입니다. 코드는 그대로 두고, **인터넷에 보이는 버전만** 이전 것으로 바꿉니다.

1. vercel.com → 프로젝트 → **Deployments**
2. 문제가 생기기 **직전에 잘 되던 배포**를 찾습니다(시간과 초록색 Ready 표시로 구분)
3. 그 줄 오른쪽 **⋯** 메뉴 → **Instant Rollback** (또는 **Promote**)
   - [미확인] 메뉴 이름은 Vercel 화면 버전에 따라 다를 수 있습니다
4. 1분 안에 사이트가 이전 버전으로 돌아갑니다. 접속해서 확인하세요.
5. 저에게 알려 주시면 원인을 찾아 고친 뒤 다시 배포하겠습니다.

**되돌리기로 안 되는 것:** 데이터베이스 내용, 환경변수, 외부 서비스 설정은 되돌아가지 않습니다. 이런 것을 바꾼 뒤 생긴 문제는 바꾼 값을 원래대로 돌려놓아야 합니다. 그래서 **바꾸기 전 값을 메모해 두는 습관**이 중요합니다.

## 4. 오류 기록 보는 법

| 어디                        | 무엇이 보이나                                     | 보는 법                                                                                                                          |
| --------------------------- | ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **Sentry** (오류 자동 수집) | 손님 화면·서버에서 난 오류 목록, 몇 명이 겪었는지 | sentry.io → 프로젝트 → **Issues**. 새로 생긴 오류가 맨 위. 연결은 [체크리스트 6단계](SETUP_CHECKLIST.md#6-sentry-오류-자동-수집) |
| **Vercel Logs** (서버 기록) | 서버가 남긴 모든 기록                             | Vercel → 프로젝트 → **Logs**. 빨간(Error) 줄 위주로 봅니다. 시간 범위를 문제 시각으로 맞추세요                                   |
| **Supabase Logs**           | 데이터베이스·로그인 쪽 기록                       | Supabase → **Logs** (또는 Log Explorer)                                                                                          |
| **GitHub Actions**          | 자동 검사·매일 깨우기 실행 결과                   | GitHub 저장소 → **Actions** 탭. 빨간 ✗ 가 있으면 클릭해서 확인                                                                   |

기록 안의 낯선 글자를 해석하려 애쓰지 않아도 됩니다. **문제 시각 전후의 빨간 줄을 복사해서** 보내 주시면 됩니다.

쇼핑몰이 남기는 기록에는 앞에 꼬리표가 붙어 있어 찾기 쉽습니다. 예) `[health]` 상태 확인, `[csp-report]` 보안 규칙 위반 보고.

## 6. 저에게 알려 주실 때

아래 양식을 복사해서 채워 주시면 가장 빨리 해결할 수 있습니다. 모르는 칸은 비워 두셔도 됩니다.

```
[무슨 일]      예) 결제 버튼을 누르면 흰 화면이 나옴
[언제부터]     예) 오늘 오후 3시쯤, 배포 직후
[누가]         예) 나만 / 손님 여러 명 / 모두
[어디서]       예) 휴대폰 크롬, /ko/checkout 화면
[/api/health]  예) {"ok":true,"backend":"supabase"}
[최근 바꾼 것] 예) 오후 2시 50분에 배포, CSP_ENFORCE=1 추가
[이미 해 본 것] 예) 새로고침, 다른 브라우저
[첨부]         화면 캡처, 오류 기록 몇 줄 (비밀 키가 보이면 가려 주세요)
```

## 7. 평소에 해 둘 일 (주 1회, 10분)
